# 経費集計アプリ（v0.3.3、2026-10-23 公開）

結論: freee・マネーフォワード クラウド経費・バクラク経費精算の3つから「入力」「取り込み」「集計」の型を借りた、1枚の HTML（index.html）の経費アプリ。GitHub Pages で公開済み。数人が会社と個人の経費を分けて記録し、月ごとに科目別・人別で集計できる。レシート写真は、各自が自分の端末に入れた Claude API キーで読むか、鍵なしならブラウザ内の OCR（Tesseract.js）で読む。v0.3 から保存先を「この端末だけ」と「シート（Google スプレッドシート、みんなで共有）」から選べる。鍵はどちらの保存先でも各自のブラウザの中にだけ残る。

## 2026-10-23 夜の修正（v0.3.3）: 鍵が「ワークスペースに紐づいていない」エラー

## 2026-10-23 夜の修正（v0.3.2）: Claude の読み取りが黙って無料OCRに落ちていた
- 症状: 鍵を登録しているのに表の「読み取り」が全部「ブラウザ内OCR」で、精度が低いまま。原因は Claude への送信が失敗して無料OCRに切り替わっていたのに、理由が画面に出なかったこと
- 直したこと: Claude の返事の長さの上限を 1024 から 4096 に上げた（これらのモデルは考える分のトークンも上限に含まれるため、JSON が途中で切れて「返事が読めない」になりうる）。失敗したときは理由を帯と表に出す（「Claude は失敗: …」）。「鍵を試す」で、鍵の有効性に続けて試験レシートの読み取りまで実際に通し、金額280円・日付2026-10-22 が読めたら緑にする。読み取りに関係ない「refusal fallback」の指定は外した
- 池田さんの環境で何が失敗していたかは、この版で「鍵を試す」を押すと赤い帯に理由が出る

## 写真をまとめて登録する（v0.3.1、2026-10-23 追加）
- 「写真で登録」の枠で写真を複数選ぶ（スマホはカメラロールから複数選択、PCは複数ドロップ）と、下に「まとめて登録」の表が出て、1枚ずつ順に読み取る（進み具合は「読み取り中 3 / 10 枚目」の帯）。一度に30枚まで
- 表の各行は、写真（押すと拡大）、読み取りの結果（Claude／ブラウザ内OCR／失敗の理由）、日付・金額・内容・科目・支払った人・精算。その場で直せる。店名を直すと科目のルールが効く。同じ日・同じ金額の明細が既にあれば「同日同額あり」の印
- 「まとめて登録する」で、日付と金額が入っている行だけ登録する（画像はその端末に残り、シート保存中はシートにも送る）。日付か金額が無い行は表に残るので、直すか削除する。「やめる」で表ごと捨てる
- 読み取り中は区分の切り替えができない。1枚だけ選んだときは今まで通りの流れ
- 速さの目安: Claude の鍵があれば1枚数秒。鍵なしのブラウザ内OCRは1枚10秒前後なので、枚数が多いときは鍵ありが前提
- 確認したこと（2026-10-23）: 試験画像3枚で順に読み取り→1行の金額を消す→店名を直す→まとめて登録で、2件が画像付きで入り、残り1行が表に残ること。スマホ幅では表が横にスクロールする。シート保存中の送信は1枚登録と同じ仕組み（queueOps）で、別途の動作確認はしていない
- 写真は1枚に1レシートで撮る（1枚に複数のレシートが写っていても分割はしない）

## 保存先をシートにする（v0.3、2026-10-23 追加）
仕組み: GAS のウェブアプリ（keihi_gas.js）が Google スプレッドシート「経費アプリ_明細」（タブ: 明細・設定）を 1 つ持ち、アプリは合言葉を付けた POST でそこに読み書きする。上のバーの「保存先」で「シート（みんなで共有）」を選び、合言葉を入れて保存すると、登録・編集・削除・精算済み・振り分け・CSV取り込み・設定の変更がシートに書かれ、開いたときとアプリに戻ったとき（前回から1分以上）にシートから読み直す。つながらないときは端末に溜め（ボタンに「未送信 N」と出る）、つながったら順番に送る。同じ明細を2台で直したときは、更新時刻が新しい方が残る。

- 端末に残るもの: 合言葉（keihi_sheet_v1）、シートの控え（keihi_cache_v1）、未送信の変更（keihi_outbox_v1）。どれもバックアップ JSON には入らない。「この端末だけ」の明細（keihi_entries_v1）は別に残っていて、保存先を戻すとまた見える
- シートに書く列: id・区分・日付・金額・科目・支払った人・内容・メモ・精算・レシート（あり/なし）・入力元・作成日時・更新日時・更新した人（APIキー画面の「自分の名前」）。この 14 列以外の項目は GAS 側で捨てる。Claude の API キーは明細に含まれない作りなので、シートにも GAS のログにも残らない（GAS は本文をログに出さず、action 名とエラー文だけ）
- レシート画像はシートに送らない。撮った端末の IndexedDB にだけ残る（他の端末では「レシート添付」の件数は出るがサムネイルは出ない）。将来 Drive に置く
- 設定（科目・支払う人・ルール）はシートの「設定」タブで共有。誰かが設定を保存すると全員に効く。シート側に設定が無い初回は、最初につないだ端末の設定が入る
- 削除・「この区分のデータを全部消す」はシートからも消え、全員の画面から消える（確認文にそう出る）。バックアップの復元はシート保存中は「足す」だけで、シートの他の明細は消さない
- シートに直接書くときは、id を空にしないこと（id が空の行や形の違う行は読み飛ばす）。日付は 2026-10-23 の形

### 合言葉は人ごと（2026-10-24 追加）
- 合言葉は 2 種類。管理者の合言葉（gas_deploy.json の key）は全員の明細が見え、設定（科目・支払う人・ルール）も書ける。名前付きの合言葉（gas_deploy.json の members、python3 deploy_gas.py --member 名前 で作る）は、その人の明細だけ見え、登録すると「支払った人」がその名前に固定され、他人の行は直せない・消せない。どれも xxxx-xxxx-xxxx の形
- 2026-10-24 時点の登録: 管理者（池田さん）、松本さん、藤原さん。一覧と合言葉は python3 deploy_gas.py --members。名前を変えるときは python3 deploy_gas.py --rename 旧 新（合言葉は変わらない。明細がある人は、シートの「支払った人」列を手で直す）
- 配り方: 公開URLと本人の合言葉を LINE などで 1 人ずつ直接伝え、グループには貼らない。本人は「保存先」→「シート（みんなで共有）」→合言葉→保存。つながると上のバーが「保存先: シート・名前」になり、「支払った人」はその名前だけになる。その端末にあった明細を送るか聞かれるので、本番の明細なら「OK」（支払った人はその名前に付け替わる）、お試しデータなら「キャンセル」
- 名前付きの合言葉の人が設定を保存しても、その端末だけに効く。共有の設定は管理者が変える（「支払う人」には管理者が全員の名前を入れておく。松本・藤原は入れてある）
- 合言葉が漏れたら: 管理者のものは gas_deploy.json の key を書き換えて python3 deploy_gas.py "合言葉変更"、人のものは --remove 名前 のあと --member 名前 で作り直す。古い合言葉の端末は「合言葉が違います」になり、未送信があれば端末に溜まったままになる（新しい合言葉を入れると送られる）
- 手元の偽 API（test/mock_api.py）の合言葉は test-key（管理者）、member-a（幹部A）、member-b（幹部B）

## 2026-10-23 の検査で直したこと（セキュリティ・動作・公開前チェックの3本をサブエージェントで実施）
- API キーは設定とは別の保存場所（keihi_apikey_v1）に分け、バックアップの JSON に入らないようにした。復元しても鍵と読み取り方は変わらない
- バックアップの復元は1件ずつ形を検証（id・日付・金額・区分・精算・文字数）し、外れた行と画像でないものは捨てて件数を出す。復元前の明細は keihi_prev_v1 に退避
- 一覧に出す値（id・日付・精算・店名など）をすべてエスケープ。細工した JSON を復元してもスクリプトは動かない（確認済み）
- CSP（Content-Security-Policy）を head に入れ、通信先を api.anthropic.com と cdn.jsdelivr.net だけに絞った。Tesseract.js は SRI（改ざん検知のハッシュ）付きで読み込む
- CSV 出力は = + - @ で始まるセルの先頭に ' を付け、表計算ソフトで数式として動かないようにした。取り込みは金額の上限（1億）と行数（5000）を付け、マイナスは返金として入れる
- カード明細 CSV の列判定を「利用日・利用金額・利用店名」優先に直した（楽天カード形式で「支払方法」を金額に取る不具合を修正）。取り込み前に先頭3行を見せる
- レシートの金額は「お支払金額・合計・税込」→「税込・計」→「小計」の順で探し、日付・時刻・電話番号を消してから数字を拾う。お預り・お釣り・現金の行は使わない。全角数字も読む
- 店名の「水道橋店」が水道光熱費に当たる誤判定を直した（ルールを 水道料・電気料・ガス料 に）。英字のキーワードは単語の区切りで見る（Panasonic が ANA に当たらない）。長いキーワードを優先
- 写真を2枚続けて入れたとき前の値が残る、読み取り中にタブを切り替えると壊れる、編集中の明細を削除すると更新が無反応、保存失敗が無言、の4つを修正
- 未精算のカードは全期間の合計に変更（立替の返し忘れ防止）。人別の未精算も出す
- 公開向けの体裁: noindex、description、theme-color、favicon、h1、label の紐づけ、スマホのタップ領域（44px）、フォーカスの枠、コントラスト、alt、Anthropic へ送られる旨の注意書き
- 幹部の本名は公開ファイルから外した。「支払う人」の初期値は「自分」だけなので、各自が設定か APIキー画面で名前を足す

## 残っているリスク（公開前に承知のうえで出したもの）
- kazuki0806.github.io 上の他のサイト（ポートフォリオなど）と保存場所（localStorage）の出どころが同じ。他のサイトにスクリプトを差し込まれると、この端末の鍵・合言葉・明細の控えを読まれうる。v0.3 で合言葉も端末に置くようになったので、この相乗りは早めに解消したい（下の「別の出どころへ移す案」）。鍵は Anthropic 側で月の利用上限を付けたものを使う
- ブラウザから Claude API を直接呼ぶ作りなので、鍵は漏れる前提で被害額に上限を付ける運用が前提
- シート保存の API は「合言葉を知っている人なら読み書きできる」。名前付きの合言葉はその人の分だけだが、管理者の合言葉が漏れると全員分が読み書きされる。漏れたら gas_deploy.json の key を変えて配置し直す。GAS 側は 1 回 500 件・1 件 200 文字までしか受けない
- 「この端末だけ」のままの人の記録は集まらない。配った後に「保存先: シート」になっているかを一度ずつ確認する

## 別の出どころへ移す案（検討結果、2026-10-23）
GitHub Pages は「アカウント（または Organization）ごとに 1 つの出どころ」で、kazuki0806.github.io の下のリポジトリはすべて同じ localStorage を共有する。別の GitHub Organization（例: kir-tools）を作って keihi だけを置けば、出どころは kir-tools.github.io になり、ポートフォリオ等とは切り離せる。ただし、その Organization に 2 つ目のサイトを置いた時点で同じ問題が戻るので「秘密を端末に持つアプリは 1 Organization に 1 つ」の決まりが要る。独自ドメインのサブドメイン（例: keihi.◯◯.jp）を当てると、アプリごとに出どころを分けられてこの決まりも不要になる。移行の作業は deploy.py の OWNER を変えて push し直す（15 分）、公開URLが変わるので幹部に配り直す、の 2 つ。端末に入れた合言葉・鍵・控えは出どころごとに別なので、新しいURLで入れ直してもらう。

## APIキーは1人1台ずつ（上のバーの「APIキー」）
- index.html は全員同じ「枠」。鍵・自分の名前・読み取り方は、それぞれの端末のブラウザの中にだけ保存される（ファイルにもバックアップにも入らない）
- 「APIキー」画面でできること: 自分の名前（支払った人の初期値）、鍵の貼り付け、モデルの選択、読み取り方の選択、「鍵を試す」で使えるかの確認、「鍵を消す」
- 鍵の出し方は2通り。各自が console.anthropic.com で発行する（請求は各自）か、池田さんのアカウントで人数ぶん発行して1本ずつ渡す（請求が1か所、鍵ごとに使用量が見える）。渡すときは本人に直接、月の利用上限を付けて
- 鍵を入れない人は、写真を入れるとブラウザ内OCR（無料）で読む。読み取り方を「写真は読み取らない」にすれば、画像は添付するだけで日付と金額は手入力になる
- 上のバーの「APIキー」の左の点が緑なら、この端末に鍵が入っている

## レシートの読み取り
- 「APIキー」画面の「レシートの読み取り方」で選ぶ。既定は「鍵があれば Claude、なければブラウザ内OCR」
- Claude: 画像を Claude API（既定 claude-opus-5-5、effort は低め）に送り、日付・金額・店名・科目・メモを JSON で受け取る。斜め・影・感熱紙でも読める。目安は画像1枚で約1,500トークンなので、Opus 5.5（入力100万トークン4ドル）で1枚1円前後。安くするならモデルを claude-haiku-5-5 に
- ブラウザ内OCR（Tesseract.js 5.1.1、cdn.jsdelivr.net から本体と辞書を取得）: 無料。写真向けに白黒化・コントラスト補正・拡大をしてから読む。池田さんの実物の写真（_test_receipt_real.jpg）では日付・金額・科目まで正しく、店名は「んばちと食堂水道必店」止まり（正しくは しんぱち食堂 水道橋店）。店名の精度はこれが限界で、上げるには Claude の鍵が要る
- 読み取りは60秒で時間切れにし、失敗の原因と「もう一度読み取る」「手で入力する」を帯に出す。入力欄は写真を入れた時点で出るので、止まっても手で打てる

## 3社から借りた型
- freee: 「AI が推測し、最後は人が確認する」流れ（読み取り結果の注意書き）、支払状況が一目で分かるカード（合計・件数・未精算・いちばん多い科目）
- バクラク: 「撮影するだけで読み取り」、同じ日・同じ金額の明細に「同日同額あり」の印、「何に使いすぎているか」をいちばん多い科目の色で見せる
- マネーフォワード: カード明細の CSV を取り込んで「振り分け待ち」で科目を決める、会計ソフトに渡せる CSV 出力

## 画面の中身
- 上のタブで 会社／個人 を切り替える。データは区分ごとに別
- 月送り（‹ ›）で月を変える。カードと集計はその月、一覧は「全期間を表示」で全部出せる
- 登録は2つの入り口。「写真で登録」は、撮る→読み取り→入った内容を確認→登録。「手で入力」は最初から入力欄が出て、写真は「レシート画像を付ける（任意）」で添付だけできる（読み取りはしない）。どちらを使うかは端末ごとに覚える
- 入力欄: 日付・金額（返金はマイナス）・内容(店名)・科目（既定は未分類）・支払った人・精算（未精算／精算済み／会社カードで精算不要）・メモ・レシート画像
- 集計: 科目別、支払った人別、直近6か月の推移、未精算の人別（全期間）
- 一覧: 絞り込み（科目・人・精算・検索）、「精算済みに」ボタン、編集、削除、レシートのサムネイル
- 取り込み／出力メニュー: CSV 取り込み、この月／全期間の CSV 出力（Excel で開ける BOM 付き）、JSON バックアップと復元、サンプルデータ（確認あり）、区分のデータ全消し
- 設定: 科目の一覧、支払う人の一覧、自動振り分けのルール（キーワード,科目）
